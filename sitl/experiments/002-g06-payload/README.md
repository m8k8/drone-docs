# 実験002：G06暫定モデルの積載比較

実施日：2026-11-16（日本時間）

G06の計画値を反映した暫定モデルで、空荷と水1L・3L・5Lを比較する。機体質量と慣性を変え、モーター・プロペラの推進能力は全ケースで固定する。前回は標準3kg機で環境と操作を確認したが、今回は計画機体に近い質量、寸法、推力特性、12S 10Ah電池を設定している。

**これは公表仕様と仮定に基づく比較試験であり、G06実機の搭載可能量や飛行時間を確定する試験ではない。** 形状・重量範囲・推力近似・電流誤差・未検証機能は[モデルと仮定](model.md)にまとめた。

## 結果

**空荷・水1L・3L・5Lを各3回、計12回実施し、全12回で判定条件を満たした。** 正式比較は日本時間17:42:47〜17:48:29に実行した。事前確認や失敗した起動試験は、この12回には含めず、下の開発記録に分けて残している。

全ホバー測定区間の推定高度は**9.994〜10.052m**、シミュレーター真値による水平位置ずれの最大値は**0.172m**、着地ずれの最大値は**0.038m（約3.8cm）**だった。これらは無風・仮想センサーの条件で得た値であり、実機の帰還精度を示すものではない。

積載が増えると、離陸点ホバーでの平均PWMは約1431.5→1506.4µsと増えた。同一の推進系で、増えた荷重を支えるために出力指令が増える挙動を確認できた。電流も増えるが、電流モデルには大きな近似誤差があるため参考値として扱う。

**水5Lケースは総質量18.4946kgで、計画の16.9kg以下という目標を満たしていない。** このモデルで飛行できたことを、実機の構造強度・積載上限・飛行時間が成立した根拠にはしない。

## 何をテストしたか

各ケースを3回ずつ、合計12回実行した。毎回、専用の実行ディレクトリと初期状態のSITLを起動し、次の順に操作する。失敗した試験も保存し、残りのケースを続ける。

1. 通信、GPS、EKF3、通常のアーム前チェックを確認。
2. 読み込まれた実質量・推力校正用質量と、主要パラメータを確認。
3. GUIDEDで通常アームし、10mへ離陸。
4. 中立スロットルでLOITERへ変更し、5シミュレーション秒待った後、10秒測定。
5. GUIDEDで離陸点から北20m・相対高度10mの地点へ移動。
6. LOITERへ変更し、5秒待った後、10秒測定。
7. RTLでホームへ戻り、着陸・自動ディスアームを確認。
8. 試験用に起動したプロセスだけを終了し、CSVとJSONを保存。

RTLは今回、離陸点から20m離れた場所から実施した。AUTOミッション、遠距離航法、障害物回避の試験ではない。

## 数字の読み方

- **高度**は飛行制御側の`GLOBAL_POSITION_INT.relative_alt`。離陸点を基準とする推定高度。
- **真値**は物理シミュレーターが持つ位置。`SIMSTATE`の整数緯度経度と`SIM_STATE`の高度を使う。実世界の測量値ではない。
- **ホバー位置ずれ**は指示したホーム／北20mの座標からの距離。**着地ずれの真値**は、実際の仮想着陸位置と仮想離陸位置との水平距離。
- 真値と推定値は別メッセージの最新値を組み合わせ、受信時差をCSVに保存する。真値緯度経度には約cm単位の量子化がある。小さい数値から実機のGPS・RTK精度を結論づけない。
- **PWM**は4基のモーターへの出力指令。表の平均はホバー中の全4基・全サンプルの平均。推力の余裕や効率を直接表す値ではない。
- **電圧・電流・消費量**は暫定モデルの参考値。高出力域の電流近似誤差が大きいため、実機の飛行時間・電源定格の判断には使わない。
- 10秒の測定窓でも、最初と最後のサンプル間は約9.9〜10.0秒となる。各回のサンプル数・時間幅はJSONに保存する。
- 3回の反復は再実行時のばらつきを観測するもの。ランダムな実環境条件を網羅した統計試験ではない。

## 開発途中で見つかった問題

成功した結果だけに置き換えず、次の事前確認も残している。

| 確認 | 観測・原因 | 対応・再確認 |
| --- | --- | --- |
| 標準3kg機の既存テスト | LOITER切替直後に高度8.43mとなり失敗。BINログでは切替からRC中立の反映まで1.033秒、スロットル1000の下降指示が残っていた | 中立を即時送信し、機体のRC値を確認。GUIDEDで高度9.5〜10.5m・垂直速度0.2m/s未満を連続2秒確認してから切替。修正後は成功 |
| G06最初の起動 | `model.json failed to load`でheartbeat待ちがタイムアウト。SITL内のファイルAPIが絶対パスの先頭`/`を外すため、モデルを開けなかった | 各試験へコピーしたモデル・設定を、その作業ディレクトリからの相対パスで指定。再試験で起動成功 |
| 4.7.2向け設定確認 | 旧名の`ARMING_CHECK`や`WPNAV_SPEED`等では現行設定に一致しない | 実行前に固定版の実名・単位へ変更。`ARMING_SKIPCHK=0`、`WP_SPD=3`等を使用 |

標準機修正後の記録は`runs/smoke-7nsmjky2/summary.json`。LOITER前の高度9.961m、垂直速度−0.04m/s、安定確認2.0秒、実時間19.58秒で全段階を完了した。元の実験001の成功記録は、その当時のコード・条件の記録として保持している。

## 再実行方法

新しい環境は先に[共通のセットアップ](../../guides/execution.md)を済ませる。以下は`drone-sitl`リポジトリ内のmacOSターミナルで実行する。

```bash
./scripts/prepare-g06.sh
./scripts/payload-suite.sh --repeats 3
```

準備スクリプトはモデルの整合性を確認し、固定版ソースへ既知のパッチだけを適用・ビルドする。想定外の上流ソース変更がある場合は上書きせず停止する。すでに同じパッチが適用されている場合はそのまま使用する。

空荷の1回だけを確認する場合：

```bash
./scripts/payload-suite.sh --payloads 0 --repeats 1
```

指定した1ケースを実行する場合：

```bash
./scripts/payload-test.sh --model config/g06/models/payload-5l.json --params config/g06/defaults.parm --label payload-5l
```

既存の`run.sh`は標準3kg機の対話操作であり、このG06モデルへ自動的には切り替わらない。今回の自動試験はQGroundControlへ通信を転送しない。可視化は保存した時系列と集計表による確認で、G06の3D表示やカメラ映像は含まない。
